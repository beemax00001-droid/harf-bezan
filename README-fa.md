# یه قرار کوچولو ❤️

یک سایت فارسی و موبایل‌پسند برای پرسیدن «حرف بزنیم؟» با دو پنل جدا:

- **پنل تو (مدیریت):** ساخت لینک اختصاصی، دیدن انتخاب دوستت به‌صورت زنده و شروع مجدد از منوی کشویی کنار صفحه.
- **پنل دوستت:** دکمه‌ی «نه» فرار می‌کند و کوچک می‌شود؛ دکمه‌ی «آره» بزرگ‌تر می‌شود. بعد از ۱۰ بار زدن «نه»، آن دکمه از دسترس خارج می‌شود. با زدن «آره»، انتخاب «فردا ظهر» یا «فردا شب» نمایش داده می‌شود.
- بعد از انتخاب زمان، استیکر گربه‌ای که همراه درخواست فرستادی با پیام «منموووونننن!» ظاهر می‌شود.

## راه‌اندازی یک‌باره‌ی Firebase

برای ارتباط دو گوشی، GitHub Pages به‌تنهایی کافی نیست؛ این پروژه از Firebase Realtime Database استفاده می‌کند. پلن رایگان Firebase برای این کاربرد سبک کافی است.

### ۱) ساخت پروژه

1. به [Firebase Console](https://console.firebase.google.com/) برو و یک پروژه بساز.
2. در صفحه‌ی پروژه، روی آیکون Web (`</>`) بزن و یک Web App ثبت کن.
3. Firebase یک کد شبیه این بهت می‌دهد:

```js
const firebaseConfig = {
  apiKey: "...",
  authDomain: "...",
  databaseURL: "...",
  projectId: "...",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "..."
};
```

4. فایل `firebase-config.js` را باز کن و مقدارهای نمونه را با مقدارهای واقعی پروژه‌ی خودت عوض کن. حواست باشد `databaseURL` را دقیقاً از بخش Realtime Database کپی کنی.

### ۲) فعال کردن ورود ناشناس

1. در Firebase از منوی **Build → Authentication** وارد شو.
2. روی **Get started** بزن.
3. در **Sign-in method** گزینه‌ی **Anonymous** را پیدا کن و Enable را روشن کن.

### ۳) ساخت دیتابیس و قراردادن قوانین

1. از **Build → Realtime Database** دیتابیس را بساز.
2. منطقه‌ی نزدیک به خودت را انتخاب کن؛ برای اروپا می‌توانی یک منطقه‌ی اروپایی انتخاب کنی.
3. وارد تب **Rules** شو.
4. محتوای کامل فایل `database.rules.json` را جایگزین قوانین فعلی کن و **Publish** بزن.

> مهم: قوانین دیتابیس را روی حالت عمومی (`read: true` و `write: true`) نگذار. قوانین این پروژه دسترسی را به سازنده‌ی اتاق و همان یک مهمان محدود می‌کند. لینک مهمان را فقط برای همان دوست بفرست.

### ۴) انتشار روی GitHub Pages

1. این ZIP را از حالت فشرده خارج کن.
2. یک repository جدید در GitHub بساز.
3. همه‌ی فایل‌ها و پوشه‌های داخل `harf-bezan` را در ریشه‌ی repository آپلود کن؛ خود پوشه‌ی `harf-bezan` را به‌عنوان یک پوشه‌ی تو در تو آپلود نکن.
4. در GitHub برو به **Settings → Pages**.
5. در بخش **Build and deployment**، گزینه‌ی **Deploy from a branch** را انتخاب کن؛ Branch را روی `main` و پوشه را روی `/ (root)` بگذار و Save کن.
6. بعد از انتشار، آدرس سایتت شبیه `https://USERNAME.github.io/REPOSITORY/` خواهد بود.

## روش استفاده

1. سایت را با همان گوشی و مرورگری که قرار است همیشه پنل مدیریت را با آن ببینی باز کن.
2. دکمه‌ی **ساخت لینک اختصاصی** را بزن.
3. از پنل، روی **کپی لینک** بزن و فقط همان لینک را برای دوستت بفرست.
4. وقتی دوستت انتخابش را کامل کند، نتیجه در پنل تو خودکار به‌روز می‌شود.
5. برای شروع دوباره، دستگیره‌ی باریک سمت راست صفحه‌ی مدیریت را بکش یا لمس کن و **شروع مجدد** را بزن.

## چند نکته‌ی مهم

- لینک مدیریت به حساب ناشناس Firebase در همان مرورگر وصل است؛ آن را در همان گوشی/مرورگر نگه دار و داده‌های سایت را پاک نکن. اگر مرورگر یا اطلاعاتش عوض شود، ممکن است دیگر مالک آن پنل شناخته نشوی.
- لینک دوستت یک‌بارمصرف است تا شخص دیگری نتواند به‌جای او وارد همان اتاق شود. با «شروع مجدد»، همان مهمان می‌تواند دوباره وارد جریان انتخاب شود؛ برای یک دوست دیگر بهتر است لینک تازه بسازی.
- نتیجه وقتی زنده دیده می‌شود که پنل تو باز و آنلاین باشد؛ اگر بسته باشد، با باز کردن دوباره‌ی همان لینک مدیریت، آخرین نتیجه بارگذاری می‌شود.
- کلیدهای Firebase داخل فایل جاوااسکریپت قابل مشاهده‌اند و این طبیعی است؛ امنیت را قوانین Realtime Database اعمال می‌کنند. قوانین را عمومی نکن.
- زمان‌ها به‌صورت عنوان «فردا ظهر» و «فردا شب» ثبت می‌شوند؛ سایت منطقه‌ی زمانی یا ساعت دقیق قرار را حدس نمی‌زند.

## ساختار فایل‌ها

- `index.html` — صفحه‌ی اصلی
- `styles.css` — طراحی، بافت‌ها و انیمیشن‌ها
- `app.js` — منطق دو پنل و اتصال زنده
- `firebase-config.js` — اطلاعات اتصال Firebase که باید تکمیل شود
- `database.rules.json` — قوانین امنیتی پیشنهادی دیتابیس
- `assets/cat-sticker.webp` — استیکر گربه‌ی ارسالی تو
